# 전국 지역 정보 조회 사용법

## 화면에서 사용하는 방법

개발 서버의 `/regions`에서 시도와 시군구를 선택한다. 첫 화면에 있는 **전국 시군구 브리핑 보기** 버튼으로도 이동할 수 있다. 서울·부산·대구·인천·제주 버튼도 해당 시도 선택 화면에 연결되어 있다.

지역을 선택하면 월간 브리핑과 관광 정보가 함께 조회된다. 월간 브리핑에는 실제 API에 등록된 최근 종료 축제와 예정 축제가 각각 최대 3개 표시된다. 자료가 없는 경우와 API 요청이 실패한 경우를 구분한다.

기존 광주 지도와 광주 대시보드 주소는 유지한다. 이번 전국 화면은 월간 브리핑과 관광 정보 조회를 제공하며, 기존 광주 전용 정책 시뮬레이션·상세 지도 등은 전국으로 확장하지 않았다.

## 프론트엔드가 전달하는 정보

프론트엔드는 `regionId`와 `district` 두 값을 사용한다. 지역 이름만 보내면 서로 다른 시도의 동구·중구를 구별할 수 없으므로, `/api/regions` 응답에 있는 ID를 사용한다. `district`는 숫자 모양이지만 문자열로 전달한다.

| 지역 | regionId | district | 관광 API 시도 / 시군구 코드 |
| --- | --- | --- | --- |
| 서울 종로구 | seoul | 11110 | 11 / 110 |
| 서울 중구 | seoul | 11140 | 11 / 140 |
| 부산 중구 | busan | 26110 | 26 / 110 |
| 광주 광산구 | gwangju | 12330 | 12 / 330 |
| 세종 | sejong | 36110 | 36110 / 36110 |

광주의 기존 `district=gwangsangu` 등 영문 별칭도 계속 사용할 수 있다. 현재 코드 목록의 통합 시도 ID는 `jeonnam-gwangju`이며, `gwangju`는 기존 광주 5개 구에 대한 호환 별칭이다. 지도에서 쓰는 통계청 경계 코드를 관광 조회 코드 대신 보내면 안 된다.

요청 예시는 다음과 같다. 인증키는 프론트엔드에 전달하지 않는다.

```text
GET /api/regions
GET /api/monthly-briefing?regionId=seoul&district=11110&month=2026-08
GET /api/district/contents?regionId=seoul&district=11110
GET /api/district/indices?regionId=busan&district=26110&baseYm=202608
```

시도를 바꾸면 시군구 선택이 초기화된다. 시군구를 고르기 전에는 데이터를 요청하지 않는다. `regionId=seoul&district=26110`처럼 소속이 다른 조합은 서버에서 400 오류로 거부한다. 지역이 바뀌면 이전 요청은 취소하고 늦게 도착한 이전 지역 응답도 무시한다.

## 다른 컴포넌트에 월간 브리핑 넣기

아래는 서울 종로구의 브리핑을 표시하는 완전한 컴포넌트 예시다. 실제 사용 시에는 선택 화면이나 상위 컴포넌트가 받은 지역 정보를 `selection`에 전달한다.

```tsx
import { RegionMonthlyBriefing } from '@/components/dashboard/MonthlyBriefing'

export function JongnoBriefing() {
  return (
    <RegionMonthlyBriefing
      selection={{ regionId: 'seoul', district: '11110' }}
      districtName="종로구"
    />
  )
}
```

`districtName`은 화면 표시용이고 실제 조회는 `selection`의 코드로 결정된다. 이름을 임의 입력하기보다 `/api/regions`에서 선택한 항목의 `name`을 함께 전달하는 것이 좋다.

## 코드가 처리되는 흐름

1. `src/data/tourismRegionCatalogue.ts`: 공식 `KorService2/ldongCode2` 응답의 지역 목록을 저장한다. 2026-09-17 조회 기준 16개 시도, 269개 시군구 항목이다. 일부 시와 그 산하 구가 모두 포함되므로 독립 지자체의 개수와 같지 않다.
2. `src/data/tourismRegions.ts`: 시도 ID, 시군구 ID, 이름, 시도 소속을 연결하고 기존 광주 별칭을 지원한다. 브라우저와 서버가 함께 사용하며 비밀값은 들어 있지 않다.
3. `server/regionCodes.ts`: 조회할 API 종류와 기준월에 맞는 코드를 선택한다. 세종 관광 콘텐츠의 36110/36110과 통계의 36/36110을 구분한다. 광주·전남 개편 전 통계 코드는 별도 보존하며, 자원 수요 API의 코드 변경 시점은 2026년 8월, 다른 통계는 7월로 처리한다.
4. 월간 브리핑의 각 수집 노드와 기존 지역 API들이 이 매핑을 사용한다. Gemini에는 선택된 지역에서 실제 수집된 근거를 전달한다.
5. 전국 방문자 원본은 시군구별로 한 번 집계하고 지역별 결과를 캐시한다. 지역별 브리핑 캐시도 분리되어 다른 지역 응답이 섞이지 않는다.

인천의 새 구처럼 경계가 바뀐 지역은 개편 전 통계를 현재 지역의 자료로 임의 연결하지 않는다. 이 경우 지원하지 않는 기간이라는 상태를 표시한다. 그 밖의 API 미제공 기간·세부 구 단위 자료는 빈 결과가 될 수 있으며, 없는 자료를 상위 도시 전체 수치로 대신하지 않는다. 아주 오래된 행정구역 변동의 전체 이력을 제공하는 서비스는 아니다.

기존 `/api/district/summary?district=all`은 호환성을 위해 광주 5개 구를 의미한다. 전국 전체 요약 요청으로 확대하지 않는다. 지역 지정 조회에는 명시적인 시군구 코드를 사용한다.

## 목록 갱신과 검증

지역 코드 목록은 요청할 때마다 외부 API를 다시 호출하지 않고 저장된 목록을 제공한다. 행정구역 변경 후 아래 명령으로 공식 목록을 갱신하고 검증한다. 코드 목록 생성에 실패하면 기존 파일을 덮어쓰지 않는다.

```powershell
npm run sync:regions
npm test
npm run test:briefing
npm run build
```

이번 변경에서는 시도 소속 검증, 동명 지역 구분, 세종 코드, 개편 전 코드, 지역별 방문자 집계·캐시 분리, 브리핑의 응답 필터링을 검사하는 테스트를 추가했다. 자동 검사 31개와 기존 브리핑 검사 13개가 통과했다. 실제 요청으로 서울 종로구 839개 및 부산 중구 190개 관광 정보, 세종의 최근·예정 축제를 확인했다.

검증 당시 Gemini 분석은 실패 상태였다. 관광 API 수집·축제 표시와 AI 분석 상태는 별개이며, AI가 실패하면 화면은 수집 근거만 제공한다. AI가 정상이라고 표시하거나 없는 진단을 만들어 채우지 않는다.
