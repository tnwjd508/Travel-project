# 전국 지역 선택과 API 코드 매핑 구현 계획

## 목표

프론트엔드에서 시도와 시군구를 선택하면 서버가 해당 지역의 관광 API 코드를 찾아 월간 브리핑과 지역 데이터를 조회한다. 기존 광주 자치구 주소와 요청 방식은 계속 지원한다.

## 구현 범위

1. 한국관광공사 법정동 코드 조회 API의 실제 전국 응답을 저장하고 시도·시군구 목록으로 정규화한다. 지역별 코드를 추측해서 채우지 않는다.
2. 공통 지역 매핑에서 현재 관광정보 코드와 과거 통계 코드를 구분한다. 기존 광주 별칭(donggu 등)은 유지한다. 같은 이름의 중구·동구는 시도와 시군구 식별자로 구별한다.
3. `/api/regions`로 프론트엔드에 선택 가능한 목록을 제공한다. 월간 브리핑과 기존 `/api/district/*`는 전국 시군구 식별자 및 선택한 시도를 검증한다.
4. 전국 지역 조회 화면을 추가하고 기존 첫 화면의 서울·부산·대구·인천·제주 선택을 연결한다. 전국 목록에서도 시도를 고를 수 있게 한다. 광주 전용 지도와 기존 대시보드는 유지한다.
5. 월간 브리핑은 부모 화면이 선택한 지역을 전달할 수 있도록 확장한다. 다른 지역 요청이 진행되는 동안 이전 지역 결과를 보여주지 않는다.

## 입력과 예외

- 대표 요청: `regionId=seoul&district=11110` → 서울특별시 종로구.
- 시도만 선택한 경우 시군구 선택을 요청한다. 임의로 다른 지역이나 첫 번째 시군구 자료를 대신 보여주지 않는다.
- 잘못된 코드, 서로 맞지 않는 시도·시군구, 이름만 있어 구별할 수 없는 입력은 오류로 처리한다.
- 세종처럼 코드 구조가 다른 지역은 실제 코드 조회 결과를 보고 별도로 처리한다.
- 행정구역 개편 이력을 확인하지 못한 기간에는 다른 지역의 과거 자료를 임의로 연결하지 않는다.
- 자료가 없거나 공급 API가 오류를 반환하면 상태를 표시한다.

## 검증

- 전국 목록의 중복·형식·시도 소속을 검사한다.
- 서울·부산 등 동명 자치구가 서로 다른 코드를 사용하는지 검사한다.
- 광주 기존 요청 호환, 과거 코드 전환, 시도 불일치 거부, 캐시 분리를 검사한다.
- 기존 백엔드 및 월간 브리핑 테스트, TypeScript 검사, 빌드를 수행한다.
- 실제 서로 다른 지역의 API 결과와 프론트엔드 지역 변경을 확인한다.

## 작업 방식

기존 문서를 보존하고 공통 매핑과 새 조회 화면을 추가하는 방식으로 진행한다. 이번에는 지역 선택부터 데이터 조회까지 한 기능을 완성한다. 광주 전용 지도·정책 시뮬레이션 등 다른 기능의 전국화는 별도 범위다.
