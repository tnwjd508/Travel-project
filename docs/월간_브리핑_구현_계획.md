# 월간 브리핑 구현 계획

## 이번 기능의 범위

대시보드의 오늘의 브리핑을 실제 관광 API 자료로 작성하는 월간 브리핑으로 교체한다. 기존 지도·KPI·다른 진단 페이지는 이번 기능의 범위에 포함하지 않는다. 기존 파일을 삭제하지 않고 서버 모듈과 월간 브리핑 컴포넌트를 추가하여 연결한다.

## 데이터와 기준

- 기본 진단 월은 한국 날짜 기준 직전 완료 월이며 최근 24개월을 선택할 수 있다.
- 방문자 수, 서비스·문화 수요, 체류·소비 강도, 관광객·소비·국제 다양성, 중심 관광지, 축제 API를 각각 조회한다.
- 사진·채용·오디오 등 월간 지역 진단과 직접 관련 없는 API는 이번 수집 대상에서 제외한다.
- 통계용 행정구역 코드와 기존 지도용 코드를 구분한다. 응답도 선택한 지역·기간과 일치하는지 확인한다.
- 날짜별 방문 수는 관광객 구분별 누적값이며 월간 순방문자로 표시하지 않는다. 지표값은 인원·원·시간으로 변환하지 않는다.
- 최근 축제는 최근 1년 이내 종료된 행사 중 최신 3개, 예정 축제는 오늘 이후 90일 이내 시작하는 행사 중 3개다. 행사 기간과 이름은 API 원문으로만 구성한다. 실제 동구 자료에서 최근 90일 종료 행사가 없었으므로 계절 축제도 확인할 수 있도록 종료 조회 범위를 1년으로 정했다.
- 2026-07-01 행정구역 개편 전후의 법정동 코드를 분리한다. 과거 통계는 당시 코드, 현재 축제는 현재 코드를 사용한다.
- 페이지 조회 제한·자료 없음·API 오류·Gemini 오류를 기록하고 다른 월의 자료로 몰래 대체하지 않는다.

## 처리 흐름

1. 서버가 지역과 월을 검증하고 API별 자료를 수집한다.
2. LangGraph가 출처별 자료를 선택하고 원문에서 검증 가능한 근거를 정규화한다.
3. Gemini가 새 근거와 앞 단계의 진단을 함께 읽어 진단을 점진적으로 병합한다.
4. 각 단계의 출처 식별자를 유지하고 최종 구조화 JSON을 검증한다.
5. 화면은 요약·핵심 진단·추천 검토사항·수집 상태·최근 및 예정 축제를 보여준다.

## 장애·보안·비용

- API 키는 서버 환경변수로만 읽고 브라우저 응답과 로그에 넣지 않는다.
- 외부 요청은 고정 API 주소, 제한된 파라미터, 타임아웃과 페이지 상한을 사용한다.
- 동일 지역·월 요청은 서버 메모리 캐시와 진행 중 요청 재사용으로 중복 호출을 줄인다. 서버리스 인스턴스 사이의 공유 캐시는 별도 운영 과제다.
- Gemini에는 공개 관광 통계와 행사 정보만 전달한다. 개인정보 저장이나 데이터베이스 추가는 없다.
- Gemini 키가 없거나 실패하면 AI 진단을 생성했다고 표시하지 않고 확보된 근거와 축제만 제공한다.
- 외부 API 텍스트는 자료로 취급하며 그 안의 명령은 실행하지 않는다.

## 검증과 완료 기준

- 날짜 경계, 지역 코드, 빈 응답, 페이지네이션, 일부 API 실패, 출처 없는 AI 결과, 단계별 병합과 캐시를 자동 검증한다.
- TypeScript 검사와 프로덕션 빌드를 통과한다.
- 사용 가능한 환경설정 범위에서 로컬 API와 화면을 확인한다. 실제 Gemini 검증을 못 한 경우 이유를 명시한다.
- 구현 후 이번 기능을 확인받고 다음 기능으로 넘어간다.
